# RAG Search Engine

A command-line movie search and Retrieval Augmented Generation project built while working through Boot.dev’s **Learn Retrieval Augmented Generation** course.

The repository explores several retrieval and generation techniques, including keyword search, semantic search, hybrid retrieval, query enhancement, reranking, evaluation, RAG, and multimodal search.

## What I Implemented

### Keyword Search

Built an inverted index with text preprocessing, unranked keyword lookup, and BM25-ranked retrieval.

The project also implements TF, IDF, and TF-IDF directly, along with the scoring concepts that lead into BM25.

### Semantic Search

Uses `all-MiniLM-L6-v2` embeddings and cosine similarity to retrieve movies based on semantic meaning rather than exact wording.

The project includes both whole-document search and chunked semantic search, where movie descriptions are split into overlapping sentence groups and ranked using the best-matching chunk.

### Hybrid Search

Combines BM25 and semantic retrieval using two strategies:

* weighted score fusion
* Reciprocal Rank Fusion (RRF)

The RRF command can optionally apply query enhancement before retrieval and reranking afterward.

### Query Enhancement

Implements LLM-based spelling correction, query rewriting, and query expansion.

These are optional capabilities available through the RRF search command rather than default steps in every retrieval or generation flow.

### Reranking

Implements three second-stage reranking approaches:

* individual LLM scoring
* batch LLM reranking
* cross-encoder reranking

The cross-encoder implementation uses `cross-encoder/ms-marco-TinyBERT-L2-v2`.

### Retrieval Augmented Generation

The RAG commands retrieve movie data with hybrid RRF search and provide the top results as context to an LLM.

Supported generation modes include direct answers, summarization, conversational responses, and citation-oriented output.

The current RAG path uses plain RRF retrieval and does not automatically apply query enhancement or reranking.

Citation markers are generated by the LLM and are not programmatically validated against the retrieved documents.

### Evaluation

Implements Precision@K, Recall@K, and F1 evaluation against a small golden dataset.

The evaluation CLI measures the plain hybrid RRF retrieval strategy by comparing returned movie titles against expected relevant titles.

A separate LLM-as-judge mode is available through the `rrf-search --evaluate` flag. This relevance scoring is part of the hybrid search CLI and is separate from the golden-dataset evaluation command.

### Multimodal Search

The project contains two separate image-related workflows.

One uses an image and text query with an LLM to produce a rewritten text search query.

The other uses `clip-ViT-B-32` to embed movie text and query images into a shared embedding space, enabling direct image-to-text retrieval with cosine similarity.

## Architecture

```text
Hybrid Search:
Query → [optional enhancement] → BM25 (Keyword) + MiniLM (Semantic) → RRF → [optional reranking] → Results

RAG:
Query → Hybrid RRF → Retrieved Context → LLM → Answer

Evaluation:
Query → Hybrid RRF → Golden Dataset Metrics

CLIP Image Search:
Image → CLIP → Movie Ranking

Vision Query Rewrite:
Image + Query → LLM → Rewritten Query
```

A few important distinctions:

* query enhancement occurs before RRF retrieval
* reranking occurs after RRF retrieval
* both are optional features of the `rrf-search` command
* the RAG commands currently use plain RRF retrieval without either step
* the evaluation CLI also measures the plain RRF path
* the vision query rewriter and CLIP retrieval are separate workflows

## Running the Project

### Requirements

* Python 3.13+
* `uv`
* `data/movies.json`
* `data/stopwords.txt`
* internet access for initial Hugging Face model downloads
* internet access whenever using OpenRouter-backed LLM features
* `OPENROUTER_API_KEY` (see below for exactly which commands need it)

Install dependencies:

```bash
uv sync
```

Set the OpenRouter API key in a local `.env` file:

```bash
OPENROUTER_API_KEY=your_api_key
```

`keyword_search_cli.py`, `semantic_search_cli.py`, and `multimodal_search_cli.py` do not require OpenRouter.

`hybrid_search_cli.py`, `augmented_generation_cli.py`, and `evaluation_cli.py` currently require `OPENROUTER_API_KEY` to be set even when the selected path itself makes no LLM call, because their modules import the query-enhancement module at load time, which validates the key eagerly.

LLM-backed features such as query enhancement, LLM reranking, RAG generation, LLM relevance evaluation, and vision-assisted query rewriting make OpenRouter API calls at runtime.

Some local models are downloaded on first use:

```text
all-MiniLM-L6-v2
clip-ViT-B-32
cross-encoder/ms-marco-TinyBERT-L2-v2
```

These models are cached locally after the initial download.

`data/movies.json` is not included in the repository and must be supplied separately.

## Example Commands

Run these commands from the `cli/` directory.

BM25 keyword search:

```bash
python keyword_search_cli.py bm25search "bear marmalade"
```

Chunked semantic search:

```bash
python semantic_search_cli.py search_chunked "cute talking bear" --limit 5
```

Hybrid RRF search:

```bash
python hybrid_search_cli.py rrf-search "movies about a talking bear" -k 60
```

RRF with optional query enhancement and reranking:

```bash
python hybrid_search_cli.py rrf-search "beer movie w/ bear" -k 60 \
  --enhance spell \
  --rerank-method cross_encoder
```

RAG:

```bash
python augmented_generation_cli.py rag "movies about a bear in london"
```

CLIP image search:

```bash
python multimodal_search_cli.py image_search ../data/paddington.jpeg
```

## Course Context

This project was built incrementally while completing Boot.dev’s **Learn Retrieval Augmented Generation** course.

The repository is a guided learning project rather than a production RAG platform or a system architecture designed entirely from scratch. Each capability was introduced progressively through the course and implemented here as working code.

Detailed chapter-by-chapter notes, diagrams, and implementation walkthroughs are documented separately.

## Limitations / Next Steps

Current limitations and possible improvements include:

* integrate query enhancement and reranking directly into the RAG flow
* automatically route vision-generated queries into retrieval
* validate generated citations against retrieved documents
* expand evaluation beyond the current RRF baseline
* improve caching and persistence
* add an API or web interface
